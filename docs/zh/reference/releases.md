# 版本更新


## 0.18.0

新增单 SM89／SM120 混合模型视频参考、自有 128 MiB CPU VAE 缓存、显式空间半采样、
常驻 SM120 音频 K/V 复用，以及画面解码／六步音频重叠。
[完整指南](../guide/complete-pipeline#reference-video)定义输入与生命周期。
引擎音频补采保持显式启用，应用自行选择默认并提供匹配调制表。

以下为五秒完整 MP4 调用，单列模型加载和服务传输之外的执行耗时：

| 场景 | RTX4090 48 GiB、BF16 双槽、44/6 Torch | RTX PRO6000 Server 96 GiB、常驻 FP8、44/6 Sage |
| --- | --- | --- |
| 512² 瞬态声音，串行 → 所选重叠方案 | 65.41 → 60.69秒（均用隐藏缓存） | 20.12 → 14.03秒（全音频上下文 → K/V＋重叠） |
| 1344×768 音乐，串行 → 所选重叠方案 | 148.08 → 142.63秒 | 49.91 → 42.55秒 |
| 512² 身份参考，完整冷编码 → 半空间缓存 | 125.02 → 61.32秒 | 47.10 → 20.84秒 |
| 1344×768 镜头参考，完整冷编码 → 半空间缓存 | 356.63 → 178.04秒 | 134.74 → 63.25秒 |

参考行同时包含 VAE 缓存与空间压缩收益。另一个完整参考 4090 对照中，VAE 从 22.62秒降至0.0034秒，
120帧解码画面相同。十组音画重叠对照的全部120帧保持一致；九组PCM逐采样相同，首条4090对白
PCM差异RMS为0.001864，对白转写一致。质量采用各场景原始要求、多时点画面与独立音频观察。
空间压缩改变脸部细节与构图，因此默认完整参考。
最终应用worker使用公共自有实现，在同一PRO6000完成三条补采I2VA和一条完整视频参考。
CPU检查覆盖生命周期清理、准入和隔离。

本次修复推理开始前的模式拒绝，权重、注意力和去噪计算保持原版本。CPU合同检查已通过。

## 0.17.0

`veda_dense_edge_layers=4`选择第0–3与46–49层为密集层，其余42层采用Veda。
两个CLI入口与完整pipeline接受3、4、5；默认5保持40/10。可选音频上下文阶段保留显式44/6或42/8。
SM120的Sage保持密集与稀疏INT8 QK / FP8 PV；FROST采用密集BF16、稀疏INT8 QK / FP16 PV。

同一物理RTX PRO 6000、常驻FP8权重、四步，每行固定参考图、提示与种子；表中为完整引擎秒数，
模型加载与网络交付另外记录：

| 五秒I2VA输入 | Sage 44/6 | Sage 42/8 | FROST 44/6 | FROST 42/8 |
| --- | ---: | ---: | ---: | ---: |
| 1344×768 | 46.2 | 47.0 | 47.5 | 47.0 |
| 544×960，附加六步音频 | 31.3 | 31.5 | 31.4 | 31.2 |
| 2720×1536 | 222.9 | 225.2 | 244.9 | 257.5 |

范围为三个输入场景，每配置各一次计时。原生局部显示表情、动作相位与局部细节变化，
质量按实际参考及动作要求逐场景判断；更多场景覆盖单独记录。0.16.0的四组规格对照来自两个场景族，
其闪烁/清晰度统计对应那批样本。

本版包含0.16.1的显存门槛显式设置。已发布的native与pipeline镜像在非特权用户下报告0.17.0；
摘要和不可变依赖底图见`docker/images.json`。选择Sage时单独安装该扩展。

## 0.16.1

`VFLASH_SM120_RESIDENT_GIB`可调低SM120常驻权重的显存门槛（默认90，可取24–90）。只服务实测峰值能放进
较小显卡的规格的部署（例如由调度限定为1MP五秒请求的32 GiB RTX 5090）设为30；更大的规格会以CUDA OOM
失败，而不是静默回退。SM90仍为75 GiB，其他均不变。

## 0.16.0

SM120上的`veda_dense_backend="sageattention2"`成为一个整体INT8 Q·K / FP8 P·V策略：除密集边缘层
（SageAttention 2.2.0 CUDA）外，Veda稀疏层的P·V也改用FP8。遍历、掩码、块选择与INT8 Q·K不变；V按头×通道
量化为e4m3，FP32累加。启动自检限定稀疏内核相对Veda原内核的误差（<5%），不做静默回退；回执新增
`sparse_precision`。其他后端、默认值与档案均不变。

同一RTX PRO 6000 Server、常驻FP8权重、Veda 44/6、同种子，以FROST BF16密集＋FP16稀疏P·V为基线：

| 请求 | 基线去噪 | 0.16策略去噪 | 完整请求 |
| --- | ---: | ---: | ---: |
| 2720×1536 五秒 | 211.1秒 | 182.3秒 | 276.2 → 237.8秒 |
| 1344×768 十五秒 | 110.6秒 | 96.8秒 | 149.7 → 135.3秒 |
| 1MP对白 五秒 | 28.4秒 | 26.2秒 | 43.1 → 40.4秒 |
| 0.5MP对白 五秒，0.25MP音频阶段 | 22.1秒 | 20.7秒 | 31.1 → 29.3秒 |

基线臂先运行，其第一条请求含部分去噪以外的预热。精度会改变采样轨迹；无参考指标下，四组对照的细节
亮度带逐帧变化为基线的0.97–1.02，拉普拉斯清晰度为0.96–1.01。这是有界对照，不是等价结论。

## 0.15.1

为六步音频阶段的视频上下文新增经验证的0.25MP空间预算：在默认500,000之外支持
`AudioRefinementRequest(..., context_pixels=250_000)`。仍是相同的均匀token抽样、原RoPE、全部时间步与
冻结的视频latent；其他数值路径、调度与默认值均未改变。

以发行代码（在0.15.0上放宽守卫）实测完整I2VA请求的音频阶段耗时，0.25MP对比0.5MP：

| GPU与执行方式 | 请求 | 0.25MP | 0.5MP |
| --- | --- | ---: | ---: |
| RTX 4090 48 GB，BF16块环 | 八个五秒画布，0.45–1.06 MP（中位数） | 34.1秒 | 50.6秒 |
| | 2720×1536五秒 | 42.2秒 | 65.4秒 |
| | 1920×1088十秒 | 56.0秒 | 107.4秒 |
| | 1344×768十五秒 | 75.2秒 | 160.1秒 |
| | ≤1.4 MP五秒对白（三条，中位数） | 33.6秒 | 52.2秒 |
| RTX PRO 6000 96 GB，常驻FP8 | 2720×1536五秒 | 11.9秒 | 19.9秒 |
| | 1920×1088十秒 | 16.8秒 | 32.4秒 |
| | 1344×768十五秒 | 23.5秒 | 49.2秒 |
| | 1 MP五秒对白（三条，中位数） | 7.5秒 | 14.4秒 |

不同预算下交付画面逐帧一致。Whisper large-v3-turbo对两种GPU上各三条中英文对白在两种预算及不优化时转写完全相同。
20条音轨中，0.25MP相对0.5MP的语音频段包络延迟均为0，19条相关系数0.97–1.00，一条机械声4MP为0.77；
除该条外，0.25MP与0.5MP的距离都小于0.5MP与不优化音轨的距离。Audiobox Aesthetics分数变化不超过±0.3。
这是速度与客观指标验证，不代表听感结论。

## 0.15.0

单张96 GiB SM120上的常驻I2VA改用与原生高清相同的联合预算
`宽×高×模型帧数 ≤ 2048²×124`准入，不再固定为1536×864画布。因此可覆盖1536×864十五秒、
1920×1088十秒以及2720×1536等真4MP五秒请求。SM90保持已实测的1536×864范围；块环仍是默认与
回滚方案。数值路径、调度与默认值均未改变。

在一张RTX PRO 6000 Blackwell（96 GiB）上以常驻FP8主干、Veda 44/6、两步人脸修复和六步音频修复
完成完整I2VA请求：1920×1088五秒163秒、2720×1536五秒261秒、1920×1088十秒245秒，三条请求的
显存峰值为42.1 GiB。每条视频开头、中段、结尾画面及4MP原生分辨率裁切均连贯、无平铺。这是容量与
画面资格，不代表音质结论。

## 0.14.0

图像条件原生高清的最长边合格范围放宽到2720像素。2048²总像素上限、1:4–4:1比例范围以及
`宽×高×模型帧数 ≤ 2048²×124`的联合预算均不变，因此2720×1536（16:9）、1536×2720（9:16）、
2368×1760（4:3）等真4MP画布为五秒请求。请求契约与首帧条件bundle共用
`NATIVE_HD_MAX_LONG_EDGE`；更长的边仍在模型激活前拒绝。数值路径、调度与默认值均未改变。

同一张RTX 4090（报告显存48 GiB）以BF16混合Veda 44/6完成五条完整I2VA请求，120帧画面连贯，
无平铺或重复结构：2720×1536城市与街景（672.0、658.9秒）、含人物的1536×2720（669.6秒）、
2368×1760（663.5秒）和2720×1152（462.5秒）。后三条使用未修改的发布契约。这是画面资格，
不代表音质或其他GPU结论；更长的4MP请求仍超出联合预算。

## 0.13.0

新增六步音频的显式、自有请求隐藏上下文复用：
`AudioRefinementRequest(..., reuse_hidden_context=True)`保持六次音频评估和视频latent，
近似复用首次非音频隐藏状态，默认仍完整重算。双槽按逻辑层持有缓存；常驻接口具有
CPU覆盖。GPU试听/速度证据限两组512²/5秒RTX4090，音频阶段约少34%。显存边界、
异常恢复和未测范围见[完整流水线](../guide/complete-pipeline.md#audio-hidden-context)。

## 0.11.0

新增可选的仅音频六步修复，以约0.5MP空间条件保留原视频和全部时间位置，使用匹配调制表与解码余量保护。
要求显式选择单卡常驻hybrid I2VA、Veda 44/6；进度区分四步主生成和额外六步，默认行为不变。
独立的原生/文本FP8工厂与完整上下文按行分块减少集成方重复实现，不下载权重或扩大准入。

两组独立高清场景通过新音频接口及公共FP8工厂复现全部画面与交付PCM；另两组较小画布的
人脸/音频联合请求保持此前最佳人脸画面，并在人脸拼接中保留已修复音轨。
这是限定RTX PRO 6000 Server集成证据，私有扩展容量、应用资产和生产采用另验。
可选源场景条件复用仍保留明确的实验资格边界，不随包提供模型权重。


## 0.10.0

新增显式`batch2-fp16-norm-reuse-untiled`人脸编码配置，支持512方形、124帧输入。
移除重叠空间编码块，保留时间块复用，成功或失败均恢复模型状态；普通编码及MP4/RGB默认保持。

约48GiB的RTX4090上三个集成场景均减少完整人脸阶段耗时。精确公开配置另在一个场景中复现
私有原型全部120帧最终RGB；这仅证明与该原型一致，并不等同此前分块编码器。
空间上下文、归一化和部分细节改变，显存增加，计时与质量边界见完整流水线文档。
不新增修复模型、权重或应用调度。wheel、源码包和两类镜像已发布，接入应用仍需显式选择；
发行不会自动更改其已部署配置。

## 能力状态 {#availability}

当前支持的输入模式、精度选择与联合容量限制，以[配置与硬件说明](../guide/profiles)
和[完整链路合同](../guide/complete-pipeline)为准。[镜像清单](https://github.com/Hansimov/vflash/blob/main/docker/images.json)
标识已发布的原生与完整管线镜像。上方历史记录中的包和镜像可用性只描述各自发布时刻，
不覆盖当前支持表。模型权重需单独获取并遵守其许可。

新增硬件、模式与修复功能须分别完成实际执行和完整媒体验证。
源码选项不会自动升级已部署的服务。
